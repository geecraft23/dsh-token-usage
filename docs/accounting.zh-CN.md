# 统计口径与配置

## 统计口径

记录 DSH 公共 `llm/stream` 扩展点上的每次调用，包含同进程聊天、工具循环之后的请求、压缩及标题生成。一次请求的多次 `usage` 上报是累计快照，只保留最新值；不同重试请求分别计数。响应内容原样返回，不读取提示词、回答或密钥用于保存。

DSH 的 `inputTokens` 是**未缓存输入**。本插件展示的输入＝未缓存输入＋缓存读取＋缓存写入；总量＝输入＋输出。思考 token 已属于输出，不额外相加。输入会重复计算每次请求发送的历史上下文，这是累计请求用量，不是独立文本字数或当前上下文长度。

未返回 `usage` 的请求记为“未返回用量”，不虚构 tokenizer 估算。界面中的 token 数值是已知部分；取消和失败请求如已上报用量，仍保留这部分数值。崩溃或强制退出前没有结算的记录显示为“未结束”。模型服务本身没有上报的消耗无法恢复，因此本插件不是计费账单、供应商审计记录或订阅剩余额度。

实时采集从插件启用后开始；0.3 支持用户主动扫描并导入旧会话中已保存的用量。重放／模拟插件如果通过同一 LLM 扩展点输出用量，也属于观测请求；测试应使用隔离的 `DSH_HOME`，不要写入正式账本。

“本地”按使用者定义的部署方式分类：本机、局域网、自建远程服务或租用 GPU 都可标记为本地。不能仅凭模型名、是否开源或 URL 是否为公网判断，因此默认是“未分类”。分类不表示零成本。

日期按请求开始时间归属，结束日期包含整天。每日分组采用浏览器当前的固定 UTC 偏移（页面有标注）；不是跨夏令时规则的历史时区换算。

## 历史导入

导入读取当前 Profile 的公共 `sessionPersistence` 服务，由运行中的 DSH 验证格式并读取压缩日志。它只打开只读句柄，不改写会话文件。未提供该服务的 Profile 可以继续实时计数，但无法导入。当前验证目标为 DSH 0.1.5-rc.1；主机不支持的格式、损坏或缺失文件会在扫描中报告。

每个自有的 `assistant/message`、`assistant/attempt` 结算事件只提取最后一次累计用量快照；实际调用模型的 `compaction/summary` 也计入。失败／取消请求保留已保存的用量，无用量的请求标记缺失。标题请求事件只保存了请求，没有响应用量，因此单列覆盖缺口；无法恢复已删除的日志或其他未记录的辅助调用。

历史请求以会话 ID、事件序号及事件类型生成持久身份。分支继承的前缀不再次计数；缺失原会话时会报告继承部分未恢复。与旧实时账本核对时，要求同会话、provider、model 和用途，时间区间重叠，且结束时间与完整用量唯一匹配。没有重叠才新增；有重叠但不能可靠匹配时跳过并显示。写入事务会再次核对，避免预览后实时采集或其他 Profile 的导入导致重复。

历史日期采用最早保存的流片段时间，压缩请求采用已保存的压缩开始时间，缺失时采用结算事件时间；这些记录无法精确还原网络请求发起时刻。统计口径分别显示插件启用日期和最早用量日期。部署分类与输入／输出仍是独立维度，历史数据使用同一套分类与导出规则。

扫描和导入在服务器上运行，关闭面板不会取消。点击取消保留已提交记录；重新扫描即可继续。预览和进度保存在进程内，重启后需重新扫描；请求身份与去重关系保存在 SQLite 中。扫描默认最多 10,000 个会话、100,000 条请求，超限则停止、不允许导入不完整预览。可在插件配置中设置 `historyMaxSessions`（1–100,000）、`historyMaxRequests`（1–1,000,000）和 `historyMatchToleranceMs`（默认 100 毫秒，0–5,000）。界面最多展示 100 条问题明细。

账本版本 1 首次升级前使用 SQLite 一致性快照自动备份，随后事务迁移至版本 2；备份失败会停止加载。分类和原请求保留。共用账本的旧插件应一起升级，降级需停止所有写入者并恢复旧备份，备份后的记录也会回退。

## 数据与配置

默认账本位于 `$DSH_HOME/token-usage/usage.sqlite`；未设置 `DSH_HOME` 时是 `~/.dsh/token-usage/usage.sqlite`。重启、删除 DSH 会话、插件重载不会重置累计值。WAL 模式允许多个本机 DSH 进程共用文件；不要放到网络文件系统。备份时停止写入，或使用 SQLite 的备份工具。

账本保存请求 ID、时间、服务和模型 ID、会话 ID、调用用途、结果状态及 token 数字。它不保存对话正文、接口地址、API key 或 Cookie。调用过程中的账本写入失败不打断模型响应；后续写入会重试尚未保存的记录，页面显示写入异常提示。关闭进程前仍未保存的记录可能丢失。

可以在 Profile 的 `cordis.patch.yml` 配置存储位置和来源规则：

```yaml
- id: token-usage
  config:
    databasePath: /absolute/path/to/usage.sqlite
    busyTimeoutMs: 1000
    rules:
      - provider: deepseek
        source: cloud
      - provider: your-self-hosted-provider
        source: local
```

规则使用精确 provider ID，可增加 `model` 只匹配一个模型。精确模型规则优先于 provider 规则，设置页保存的分类优先于规则。未知配置和不支持的账本版本会拒绝加载。

## 配置兼容

新配置使用 `source: local`（本地）、`source: cloud`（云端）或 `source: unclassified`（未分类）。旧配置的 `offline` 对应本地，`online` 对应云端，仍可加载。账本内部保留旧标识以延续历史记录；页面统一显示本地／云端，JSON 导出使用新标识与 `formatVersion: 2`。这些兼容字段不表示输入或输出方向。
