# 0.3.0 开发目标：补全历史 Token 记录

状态：0.3.0 实现与本地验收完成。本文保留开发范围与验收标准，正式发布及 Registry 验证结果见 [GitHub Releases](https://github.com/geecraft23/dsh-token-usage/releases)。

## 用户可见结果

在「设置 → Token 用量」中导入本地 DSH 旧会话实际保存的用量，让累计值、活动图、模型明细、本地／云端统计及 JSON 导出包含可恢复的历史数据。保留已认可的圆角色块、90／30 天切换和 K／M／B 显示。

“补全”指恢复日志中确实存在的记录。已删除、无法读取或没有保存用量的请求不能恢复成精确数字；界面应明确显示覆盖范围和缺失原因。

## 本版范围

1. **扫描与预览**：扫描当前 DSH 数据目录中的历史会话，显示会话数、时间范围、可导入用量、重复项和无法解析项；不读取外部模型账号的用量。
2. **历史导入**：读取已验证版本的会话日志，恢复请求日期、服务、模型、输入、输出及已保存的缓存用量。对日志格式进行版本识别，不将不支持的文件当成空会话。
3. **去重与增量**：同一份历史重复导入不增加计数；导入与实时采集重叠时，每次实际请求只算一次；复制、分支和再次扫描已有会话也不能重算共享记录。
4. **分类延续**：历史记录使用与新记录相同的 provider＋model 分类规则，保留用户已保存的本地／云端标签。归属未知的记录明确列为未分类，不根据模型名猜测。
5. **进度与结果**：导入可取消、可重试，显示已导入、已存在、缺失、无法确定是否重复和读取失败的数量。导入失败不破坏原账本或阻断正常模型请求。
6. **统一报表**：导入成功后，刷新图表、按模型和部署位置的明细及导出；区分插件启用时间与历史记录覆盖时间，避免把“开始记录于”误当成最早历史日期。

## 已核实的实现约束

- 新版 DSH 日志中的原始请求标识、用量事件及模型归属；不能把会话级、轮次级累计量和单次请求量重复相加。
- 聊天、重试、失败、压缩和标题请求分别保存了什么数据；仅导入能够明确归属的用量。
- 分支会话和复制日志如何保留原始事件身份，压缩日志的读取方式如何兼容运行中的 DSH。
- 0.2.0 实时账本为请求自行生成 UUID，历史事件未必包含同一个 ID。必须设计可验证的重叠匹配与冲突处理；不能只按“日期相同”或“Token 数相同”删除记录，也不能仅用插件启用时间截断，因为中间停用时可能存在漏记。
- 导入状态、来源标识和迁移记录的存储方式；升级前备份账本，迁移和批次写入需要可恢复。

## 验收标准

- [x] 包含本地和云端、多个模型的确定性日志样例，导入后的输入、输出、缓存及总量与预期精确一致。
- [x] 重复导入、重启后再次导入、导入新增日志，都只增加尚未计数的请求。
- [x] 实时采集与历史导入重叠、相同用量的不同请求、重试、复制和分支会话均有去重验证；无法确定的重叠项不擅自累加，向用户列出。
- [x] 缺失用量、部分上报、损坏日志、不支持的版本、取消及恢复均有可见结果，不静默吞掉错误或伪造零值。
- [x] 现有本地／云端分类、账本记录及其他 DSH 插件配置保持完整。
- [x] 使用本地真实历史的只读快照在隔离环境验收，逐项对账后再导入日常账本；不把演示记录写进正式统计。
- 发布验收：0.3.0 安装包和 npm 正式包分别完成 DSH Profile 运行验证，更新中英文 README、截图、统计口径与发布说明。
